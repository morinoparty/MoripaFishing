MoripaFishingは以下のディレクトリ配置をサポートしています。

## ディレクトリ

```bash
plugins/MoripaFishing/
├── config.json
├── translation/
│   ├── en_US.properties
│   └── ja_JP.properties
├── fish/
│    └── **/*.json      # 配置は自由 (サブディレクトリも読み込む)
├── world/
│    └── <world_id>.json
└── rarity/
     └── **/*.json      # 配置は自由 (サブディレクトリも読み込む)
```

各ディレクトリは起動時に存在しなければ自動的に作成されます。そのため初回起動後は上記の構成が揃った状態になります。

`config.json`はファイルが存在しない場合、あるいは0バイトの場合に、`ConfigData`の既定値で自動生成されます。ルートディレクトリに置かれる設定ファイルはこの1つだけです。

## ファイル名とID

`world/`のファイル名は、表示名ではなくワールドID（`<world_id>.json`）と一致させる必要があります。一致しないファイルは警告を出してスキップされます。

`fish/`と`rarity/`はサブディレクトリも含めて拡張子が`json`のファイルをすべて読み込みます。IDはファイルの中の`id`で決まるため、ファイル名とディレクトリ構成は自由です。プラグインがファイルを移動することはありません。

## プラグイン側からの書き戻し

`world/<world_id>.json`は、`/mf world config ...` などでスポーン地点やワールドボーダーを変更したときにプラグイン側から上書きされます。このファイルが存在するIDが釣りワールドとして定義されます。サーバー稼働中にファイルを直接編集すると、書き戻しによって変更が失われることがあります。手編集はサーバー停止中に行うか、編集後に`/mf reload`で反映させてください。

## ジェネレーターの定義

ワールドジェネレーターの定義はCore本体ではなく、`world-lifecycle`統合プラグイン（Core に必須依存）の内部形式として管理されます。配置先はそのプラグインのデータフォルダ配下です。

```bash
plugins/MoripaFishing-Integration-WorldLifecycle/
└── generator/
     └── <generator_id>.json
```

初回起動時に`terra`、`void`、`normal`の3つの既定ジェネレーターが書き出されます。Core単体では`plugins/MoripaFishing/generator/`は使われません。
