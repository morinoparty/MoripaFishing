## 補足

### 一覧について

`list` は定義済み (設定ファイルが存在する) の釣りワールドを `- <表示名> (<id>) <Bukkit ワールドのキー> [managed|external, loaded|unloaded]` の形式で表示します。`external` は既存のワールドを登録した外部ワールド、`unloaded` は対応する Bukkit ワールドがまだロードされていないことを示します。

### 移動について

`transfer` は対象の Bukkit ワールドがロードされていない場合、`World <id> is not loaded.` を返して何もしません。テレポート先は、管理ワールドではワールド設定の `world.spawn`、外部ワールドでは Bukkit ワールドのスポーン地点です。

存在しない釣りワールド ID を指定したコマンドは、`Unknown fishing world: <id>` で失敗します。

### ワールドの作成について

`create` はジェネレーターの指定が必須で、省略できません。ジェネレーター ID の補完候補は WorldLifecycle Integration から取得します。Integration が導入されていない場合や、ID が不正・重複している場合、作成に失敗した場合、サーバーの起動が完了していない場合は `Failed to create world <id>. See the server log.` を返し、設定ファイルも残しません。失敗の理由はサーバーログに出ます。作成したワールドの表示名は、既定ロケールのワールド ID になります。

### ワールドの削除について

`delete` は釣りワールドの定義 (設定ファイル) を削除し、ディスク上のワールドフォルダーは残したままにします。実行後のメッセージにも、フォルダーが削除されていないことが明示されます。ロード済みのワールドを削除するには、[WorldLifecycle Integration](/integration/world-lifecycle) によるアンロードが必要です。未ロードのワールドは Integration が無くても削除できます。[外部ワールド](/format/data/world#既存のワールドで釣りをする) は登録を外すだけで、Bukkit ワールドはアンロードしません。

### 設定コマンドについて

設定コマンドは設定ファイルを保存し、ロード済みのワールドへすぐに適用させます。Bukkit ワールドへ実際に反映するのは Integration が導入されている場合のみです。

`config set spawn` は実行者の現在位置をスポーン座標として保存するため、プレイヤーからのみ実行できます。`config set center` は座標を指定して実行することもできますが、`x` と `z` を省略した場合は実行者の現在位置が使われるため、その形式ではプレイヤー専用となります。コンソールから省略して実行すると `x and z are required from the console.` を返します。

`config set center` と `config set size` は、ボーダーが管理対象外 (`border: null`) のワールドでは既定のボーダー (中心 `0, 0`・サイズ `100`) を元に値を設定し、ボーダーを管理対象に戻します。`config unset border` はボーダーを管理対象外にし、以降 MoripaFishing はそのワールドのボーダーに触れません。

外部ワールドではスポーンとボーダーを MoripaFishing が管理しないため、`config set spawn`・`config set center`・`config set size`・`config unset border` は `World <id> is an external world. MoripaFishing does not modify it.` を返して何もしません。

`config view` はワールド設定を JSON にエンコードした内容と、魚の抽選条件に使う現在の天候 (`weather: <天候>`) を出力します。
