## 重要

- このリポジトリは `MoripaFishing` のモノレポです。
- 実装前に、必ず現在のコード・ディレクトリ構成・既存ルールを確認し、別プロジェクトの前提で判断しないでください。
- 現在は開発中のため、後方互換性は考慮しません。API・SPI・設定ファイルの形式・イベント・コマンドの破壊的変更をためらわず、最もきれいな設計を優先してください。
- 互換性のためのシム（非推奨エイリアス、旧形式の読み替え、マイグレーション処理など）は負債になるため実装しないでください。
- ただし 1.0.0 以降は互換性を考慮し、破壊的変更を避けるか移行手段を用意してください（破壊的変更はメジャーバージョンを上げます）。
- コンテキスト不足で誤実装の可能性が高い場合のみ、短く確認してください。

## 作業開始準備

- 作業開始時に `git status` でワークツリーを確認してください。
- 指示内容と無関係な変更が多い場合は、巻き込まずに進められるかを先に判断してください。
- 既存の変更が今回の修正と衝突する場合のみ、作業前にユーザーへ確認してください。

## 作業の進め方

- まず関連ファイルを読み、実際の構成に沿って変更してください。
- モジュール間の責務分離（`api` / `bukkit` / `integrations` / `addons`）を崩さないでください。
- ドキュメント変更が必要な場合は `docs/` 配下の Fumadocs 構成に合わせて更新してください。
- 作業後は `task check`（`ktlintFormat`・`detekt`・`test`）を実行し、必要なら `task build` も実行してください。
